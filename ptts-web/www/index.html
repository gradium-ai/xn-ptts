checking WebGPU…

The whole model runs in this tab: the flow-matching LM and the Mimi decoder are WGSL compute shaders driven by xn's WebGPU backend through wasm. No server does any inference — the page only downloads weights.

Load

Threads set xn's worker count. On this page that changes nothing: xn's threading lives in its CPU backend and the WebGPU backend makes no rayon call, and this wasm build has no atomics, so it is single-threaded either way. Kept as a control because it is one natively, where it matters a great deal.

f16 needs the adapter to report WGSL shader-f16. The q8_0 dtypes do not work in a browser yet: xn quantizes weights by reading them back to the host (Q8Tensor::quantize), and a browser cannot block on a readback. They are listed because the same build runs them natively.

Pick a source and load. Weights are a few hundred MB and the browser caches them.
